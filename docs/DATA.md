# 价格数据维护

`data/prices.json` 是数据主文件；`data/prices.js` 是供 `file://` 离线打开的生成副本。HTTP(S) 页面启动后只异步读取本站 JSON，数据采集在站点之外统一执行。

广东来源是[广东省发展和改革委员会业务公告](https://drc.gd.gov.cn/ywgg/)。运行 `powershell -NoProfile -File .\scripts\update-guangdong.ps1` 可读取已生效公告并更新两个文件。脚本验证官网域名、公告标题、92/95/0 号柴油价格、合理价格范围、与现有历史的衔接和输出文件的一致性；任一公告解析失败或同日价格冲突就停止，不用猜测值填空。目前取列表中最近 12 篇，旧历史记录会保留。

`npm run validate:data` 可单独校验本地 JSON 与 JS 副本。GitHub Actions 在 `main` 推送、手动触发和北京时间每天 08:00 定时执行抓取、校验、测试及 Pages 部署。只有完整成功才会发布；失败时线上页面保留上次可信快照与核对日期。每次成功核对可更新 `checkedAt`，即使价格未变化；同一天无文件变化则不提交新数据。

## 录入原则

1. 优先使用各省发展改革部门公开的成品油价格通知。记录来源 URL、价格执行时间和人工核对日期。
2. `grades[油号].price` 只填有可靠来源的当前参考价；未核实填 `null`。不把其他油号或其他省份的价格推算成官方价。
3. `history` 只追加真实历史记录，格式为 `{ date: "YYYY-MM-DD", price: 8.63, sourceUrl: "https://..." }`。日期是价格生效日，价格单位为元/升。同一日期不要重复录入。
4. `nextAdjustment.dateLabel` 只填已核实的正式调价窗口，并同时填写 `sourceName`、`sourceUrl`。
5. `forecast` 是独立的市场预测。填写预测时一并记录描述、来源、链接和更新时间；预测失效后清空或更新，绝不把它写进正式油价。
6. 数据有变化时更新该地区的 `checkedAt`，再检查页面上的价格、历史图和计算结果。不要仅因网页访问成功就声称油价在加油站实时成交。

## 增加地区

在 `regions` 中添加唯一地区键，包含 `name`、`priceScope`、`checkedAt`、`source`、`effectiveLabel`、`grades`、`nextAdjustment` 与 `forecast`。页面的地区选择框和价格卡片都读取同一个 `name`，避免两处地名不一致。广东公告覆盖全省，因此名称只写“广东”，适用范围由 `priceScope` 说明。若官方为省内特殊区域单独定价，再单独建键并解释适用范围。增加地区后需要从 JSON 重新生成 JS 副本；可先参照广东脚本中的生成步骤，后续应抽成共享构建命令。

## 当前数据边界

- 2026-09-28 核对到广东 92、95 号汽油及 0 号柴油价格；98 号暂不展示数字。
- 历史包含广东省发改委近 12 篇已生效调价公告，图上没有示意节点。
- 下一轮调价窗口和涨跌预测暂无可核实数据，保持空值。
- 站点实付价格可能与省级最高零售价不同，行程计算框允许单独输入。

## 推荐的线上更新方式

统一任务定期抓取官方公告并生成经校验的 JSON，网站仅提供这份小型数据文件。用户打开页面时先看内置快照，再异步检查本站文件；网络失败就保留旧值并显示旧核对日期。调价日可以提高检查频率，其他日期每天检查即可。页面的异步 `fetch` 不会阻塞计算，也不需要每个用户浏览器运行 Web Worker 或解析政府网站。全国扩展时，每省独立适配并保留失败隔离。原始公告不属于本站 MIT 代码许可，详见 [使用边界](RIGHTS.md)。
