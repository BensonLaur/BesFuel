发布端兼容原有 FC 格式及基础校验摘要。函数额外采集海南、江西价表，以及湖南原始 XLS 并计算 SHA256，通过同一私有 OSS 快照交给发布端；新增证据单独校验解析器摘要、来源、日期及附件哈希。每轮核验报告保存为 Actions 的 `automatic-review` artifact，保留 14 天；价格和历史仍提交进仓库。

文件读取器独立于 FC 基础采集摘要；后续仅修复 PDF/Word 解析规则时，可通过 GitHub 发布，无需再次上传函数。旧 FC 未附带 `evidence` 时维持原来的公告监测行为；不会把这 11 项宣称为已自动核价。新包部署后返回 `counts.evidence.total: 5`，须确认 `passed: 5`、`failed: 0`，再验收发布报告中对应 11 项的 `automatic: true`。

## 保留与拦截

- 来源失败时保留该地区旧价格及旧核对日期，其他通过的地区可以更新。
- 非官方链接、单位或表头改变、缺油号、同日价格冲突、生效日期超前等情况拒绝写入。
- 只提供最新一条记录的监测项目，如果检查中断超过三天且出现其间的新调价，会要求先补历史，避免将遗漏期间画成价格不变。海南、江西会读取首页仍列出的多期公告。
- 图片价表、尚未支持的附件格式、辽宁和新疆其余地区的升价依据、青海具体地域归属及西安历史缺口，仍不能靠运行成功就宣称已核实。
- 黑龙江现有系数在 2026-10-31 到期。未取得并核实新季系数时，11-01 起隐藏失效升价并产生新的复核提醒。尚未实现自动发现及导入新季系数。
- 98 号是企业自主定价，不生成省级统一价格。用户仍可输入实际加油价。

## 提醒规则

提醒采用本仓库 GitHub Issue，并提及仓库所有者；通知渠道由用户的 GitHub 通知设置决定。没有新增异常时不发送例行消息。

- 网络、TLS、DNS、HTTP 错误连续三个不同发布运行仍相同，才创建提醒；不因一次临时波动通知。
- 新公告无法解析、价格冲突、季节系数失效等数据问题立即提醒。
- 以地区、异常类别和官方依据生成指纹。同一异常不重复开 Issue；新的异常依据出现时关闭旧记录并创建新记录，恢复后自动关闭。
- 附件解析失败的指纹包含原文文件哈希；相同文件失败不反复提醒，同 URL 被更换为新问题文件时可以提醒。临时文件路径不会影响指纹。旧问题转为短暂网络故障后再恢复，也能关闭此前记录。
- 已经告知用户的辽宁旧吨价缺口作为初始基线，不再次通知；出现新公告时会形成新指纹。
- 写入提醒成功后才保存去重状态；API 写入后重试也会按远端指纹检查，避免重复提醒。提醒失败会让运行报告失败，不静默宣称已通知。

工作流给发布作业增加 `issues: write`，只用于上述异常记录；不扩大阿里云只读角色权限。流程自身失败仍沿用 GitHub 原有的运行失败通知。

## 验证入口

`npm test` 包含官方 HTML 摘录、自动入库的日期/单位/冲突/回退测试，以及异常等待、去重、恢复和重试测试。`python -m unittest discover -s tests -p '*_test.py'` 校验湖南 XLS 及吉林、云南、四川真实附件的列语义、分价区、生效时间和异常变体。Python 3.12 Windows 发布环境的全部读取依赖及传递依赖均固定版本和 wheel SHA256。

第二轮另用 8-28、9-11、9-24 三期共 15 份真实官方文件对照既有人工核价记录，并验证 11 个价区在发布端不访问省级网站时全部通过。正式环境须使用新上传包产生的快照验收，不能将本机模拟结果上传 OSS 或修改其时间冒充正式采集。
