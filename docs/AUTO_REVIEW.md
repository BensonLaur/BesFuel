## 提醒规则

提醒统一维护本仓库的一条 `[油价核验] 异常事项汇总` Issue，展示新增或变化、持续事项、最近已恢复事项，列出来源和建议下一步。首次创建时提及仓库所有者；以后只有已确认的事项集合或异常依据变化时，才更新正文并发送一条汇总评论。无变化时不调用 GitHub API，不更新正文、不评论、不发送例行消息；运行次数、检查日期、结果顺序变化不会触发通知。通知渠道仍由用户的 GitHub 通知设置决定。

- 网络、TLS、DNS、HTTP 错误连续三个不同发布运行仍相同，才创建提醒；不因一次临时波动通知。
- 新公告无法解析、价格冲突、季节系数失效等数据问题立即提醒。
- 全国市场估算纳入同一汇总：来源解析或交叉校验冲突立即提醒，网络错误连续三轮相同才提醒；本轮估算超过两天未更新也提醒。保留计算日期及实际第三方链接，恢复后移入已恢复事项。预测检查未执行、报告缺失或日期不符不会计作成功。
- 以地区、异常类别和官方依据生成指纹。同一异常保持安静，新公告、不同的核验问题、恢复或恢复后的复发都会更新同一条汇总；一轮无论涉及多少价区，最多发送一条汇总提醒。
- 附件解析失败的指纹包含原文文件哈希；相同文件失败不反复提醒，同 URL 被更换为新问题文件时可以提醒。临时文件路径不会影响指纹。旧问题转为短暂网络故障时仍保留此前已确认的待办，达到三轮门槛才变更；明确核验成功后才记作恢复，缺失的检查不算恢复。
- 汇总长期保留，全部恢复时显示零项待处理及最近恢复记录，不通过关闭/重开 Issue 制造额外通知。手动关闭过的汇总也复用原 Issue，不另开新记录。正文的“新增、持续、已恢复”分类对应最近一次变化，最近恢复列表最多保留 30 项。
- 迁移时把已提醒的地区视为持续事项，只创建一次汇总。旧地区 Issue 保持原样，汇总提供历史链接；不批量评论或关闭，避免迁移本身再次触发大量邮件，后续只以汇总为准。
- 已经告知用户的辽宁旧吨价缺口作为初始基线，不再次通知；出现新公告时会形成新指纹。
- 完整送达后才保存去重状态；远端正文及评论记录变化标识。创建/更新成功但响应丢失、评论失败、评论成功后状态未保存等情况下，重试会复用同一条汇总并补齐尚未送达的一条评论，不重复创建或评论。提醒失败会让运行报告失败，不静默宣称已通知。

核价报告生成成功后，汇总步骤也可在后续测试或发布失败时执行，数据核验待办与部署成败分别记录。相同远端变化标识还能防止失败运行尚未提交本地去重状态时反复提醒；流程本身失败仍可能收到 GitHub 原有的运行失败通知。

## 如何处理汇总中的事项

汇总是便于交给 Codex 的采集维护清单，不表示每条都要求用户手工核价。默认由 Codex 按官方原文及附件重放，定位采集/解析问题，修复适配器并补充测试，再由发布工作流验证恢复。当前提醒脚本不会自动启动 Codex、生成修复代码或安排桌面自动化。

- 已有采集器报地址、日期、单位、表头或适用范围异常时，先检查新公告与原规则的差异。来源正常但规则过窄的情况可以修复，仍保留对非官网链接、单位冲突和价格回退的拦截。
- 图片价表及扫描附件可以逐步补充可复核的识别与结构化校验；必须保留原始证据，并独立核对油号、价区、单位、生效日和数值。当前尚未实现的解析能力不代表来源永远不能自动化，也不能直接把模型猜测当作官方价格。
- 网络或临时访问失败先重试后观察，超过门槛再集中处理；无需用户每次点击网站确认。
- 缺少有效官方折算系数、来源之间真实冲突或地区范围不明确时，需要先寻找可靠依据。确实没有足够依据时，Codex 应说明缺失项，再请用户决定来源或展示范围，而不是要求用户猜价格。无法可靠确认的值继续保持缺价或隐藏。

工作流给发布作业增加 `issues: write`，只用于上述异常记录；不扩大阿里云只读角色权限。流程自身失败仍沿用 GitHub 原有的运行失败通知。
