# 地区来源健康检查

记录日期：2026-10-22。这里区分“代码测试通过”“真实来源核对通过”和“网站发布成功”；三者不能互相替代。本页统计 11 个自动采集适配器、32 个公告监测器，不含独立的广东 PowerShell 采集和原油三源采集。

最终双平台检查使用相同代码及 Node.js 22，并将 IPv4/IPv6 单地址连接尝试窗口设为 2 秒。两种环境的 267 项测试均通过，但真实采集仍有失败，因此独立核对工作流保持失败状态，不能表述为全部来源已恢复。

- [修复前正式运行](https://github.com/BensonLaur/BesFuel/actions/runs/39775549077)：自动采集 3 项通过、8 项失败；公告监测 7 项通过、24 项失败、1 项待复核。
- [首轮错误详情及 curl 对照](https://github.com/BensonLaur/BesFuel/actions/runs/39778063831)：确认多数连接超时在系统 curl IPv4 直连下仍失败，且有明确的 HTTP 403 和湖南 TLS 协商错误。
- [修复后双平台检查](https://github.com/BensonLaur/BesFuel/actions/runs/39779772079)：验证解析、请求头和 TLS 修复；Ubuntu 暴露默认双栈连接窗口过短的问题。
- [最终双平台复测](https://github.com/BensonLaur/BesFuel/actions/runs/39780640947)：本页逐项结论的 Actions 依据，完整 JSON 可从该运行的 `source-health-windows-latest`、`source-health-ubuntu-latest` artifacts 下载。

各轮出口、网络及上游状态可能变化。本页只报告这些执行时点的结果，不把一次成功当作永久可用，也不把 403、超时直接归因于某一种地域封锁策略。

## 已完成的修复

- 请求错误保存 URL、耗时、HTTP 状态、底层错误码及 AggregateError/cause 链，区分超时、DNS、TLS、HTTP 拒绝、连接错误和内容校验失败。终端、Actions 摘要和 JSON 报告使用一致的分类。
- 西藏：只对校验通过的官方 HTTP 旧文章链接规范为 HTTPS，仍检查域名、端口、账号信息、路径和日期；三个价区在当前 Windows runner 复测通过。
- 江苏：为该站发送真实的 BesFuel User-Agent；原本默认请求返回 403 的列表恢复，两个平台均完成价表解析。兼容请求头限定在该站，避免影响其他门户。
- 湖南：默认 TLS 协商出现 `ERR_SSL_BAD_ECPOINT` 时，限定该域名使用已验证的标准椭圆曲线，继续验证证书和主机名；切换到“价格公布”栏目，适配列表卡片和“发文日期”。两种 Actions 环境均恢复到待人工核价状态，未凭正文吨价生成每升价。
- 安徽：适配新版标题及发布时间元素，并交叉核对已有元数据；本机恢复，Actions 仍受 403 影响。
- 内蒙古：单独验证“不作调整”公告的标题、官方来源、发布日期和正文结论，保留原每升价、价格生效时间及历史，记录新的公告状态；本机恢复，Actions 仍返回 403。
- 浙江：不调整公告不再要求新的 24 时价表，改为验证不调整结论和落款日期；本机可读，保留新公告待复核状态；Actions 仍连接超时。
- 同一执行过程的同 URL 请求复用缓存；连接重置、临时 DNS 错误最多重试一次，不反复重试访问拒绝和持续超时。重定向循环及时失败，跨域重定向仍受每个来源的官网白名单约束。
- 托管任务把双栈单地址尝试窗口从默认 250 毫秒调整为 2 秒，总请求仍受 20 秒超时约束；这是连接等待参数，不放宽数据校验。[Node.js 参数说明](https://nodejs.org/docs/latest-v22.x/api/net.html#netgetdefaultautoselectfamilyattempttimeout)

## 仍需处理的事项

当前 Windows runner 的 HTTP 403 涉及内蒙古、天津、安徽、河南；连接超时涉及广西、山西、四川、重庆、贵州、河北、青海、陕西、云南、浙江。多数同源分价区共享网站，因此一个站点不可达会影响多项结果。逐项状态见下表。

这些来源在本机已完成实际采集或公告检查，但托管 runner 的网络结果仍不同。Windows 与 Ubuntu 对照及 curl 测试表明，单纯切换操作系统、加请求头或增加等待时间不能消除全部失败。要让剩余来源长期自动更新，需要另行部署可访问这些官方网站的采集执行端（例如国内运行环境），再通过相同校验发布快照；本次没有安装后台服务或配置代理。

人工复核项目：湖南需要核实 XLS 中的每升价格；辽宁仍只有吨价依据，不能直接展示为每升价；浙江已取得新的不调整公告，保留人工确认现有价延续关系的状态。它们与网络抓取失败分开计数。

本次在本机执行正式采集和公告核对，成功项目的核对日期更新至 2026-10-22；现行每升价格均未改变。江苏经官方逐期价表校验后，历史记录由 2 条补至 23 条；内蒙古两个价区记录 10-15 不调整公告。失败或待人工复核项目不会因检查过而刷新原核对日期。267 项测试、更新器故障测试、数据校验及站点产物浏览器检查通过。

## 复查方式

```powershell
npm run check:sources
node --network-family-autoselection-attempt-timeout=2000 scripts/audit-sources.cjs --probe-curl --output="$env:TEMP/besfuel-source-health.json"
```

以上命令只读核对，不写快照、提交或部署。有来源失败时退出非零，默认报告位于系统临时目录。`--probe-curl` 对失败主机额外进行一次无代理、保留证书校验的 IPv4 请求；HTTP 403 即使 curl 进程正常退出也仍记为失败。

GitHub 中可手动运行“验证地区数据来源”；报告保留 14 天。正式 Pages 工作流继续发布经验证的旧快照以维持可用性，同时用摘要和 warning 明确显示失败、复核数量。绿色 Pages 结果不是数据来源全部成功的证明。
